# Многопоточный логгер (MPSC)

## Обзор

В этом репозитории представлена реализация потокобезопасного логгера на основе очереди с несколькими производителями и одним потребителем (multi-producer, single-consumer, MPSC). Логгер предназначен для использования в многопоточных приложениях, где множество потоков генерируют сообщения, а один выделенный поток выводит их последовательно.

Основная реализация находится в файле [`src/logger.hpp`](src/logger.hpp). Она соответствует требованиям:
- `post` может вызываться из многих потоков и должен быть быстрым, редко блокируясь.
- `run` вызывается на одном потоке и циклически печатает сообщения из очереди.
- Используются гарантии, указанные в исходном задании (длина сообщения ≤ 256 символов, остановка запрашивается только после завершения всех производителей и т.д.).

## Особенности

- **MPSC-очередь** на основе `std::mutex`, `std::condition_variable_any` и `std::deque`.
- Использование возможностей **C++20**: `std::format`, `std::stop_token`.
- Отсутствие проблем с временем жизни строк: сообщение копируется в `std::string`, поэтому переданный `std::string_view` может быть уничтожен сразу после вызова `post`.
- Минимальное удержание блокировки: вывод (`print`) выполняется **вне** критической секции, чтобы не задерживать производителей.

## Требования

- Компилятор с поддержкой **C++20** (GCC 11+, Clang 15+, LLVM 17+ из Homebrew).
- **CMake** (опционально, для сборки проекта и стандартных тестов).
- На macOS системный Apple Clang часто не имеет `std::format` и `std::stop_token`. Рекомендуется установить LLVM через Homebrew:
  ```bash
  brew install llvm
  ```

## Сборка проекта

### Вариант 1: Ручная компиляция (самый простой)

Из корня проекта скомпилируйте логгер и вашу программу, используя компилятор с поддержкой C++20. На macOS с LLVM:

```bash
/opt/homebrew/opt/llvm/bin/clang++ -std=c++20 -O2 -pthread -Isrc ваша_программа.cpp -o ваша_программа
```

Для Intel‑Mac путь будет `/usr/local/opt/llvm/bin/clang++`.

### Вариант 2: Сборка через CMake

Убедитесь, что используется компилятор с полной поддержкой C++20 (например, LLVM). Затем:

```bash
mkdir build
cd build
cmake .. -DCMAKE_CXX_COMPILER=/opt/homebrew/opt/llvm/bin/clang++ -DCMAKE_CXX_STANDARD=20
cmake --build . -j$(sysctl -n hw.ncpu)
```

> **Примечание:** Исходный тестовый каркас (в `src/tests/`) не подключён к CTest, так как не содержит функции `main` и рассчитан на передачу макросов. При желании его можно скомпилировать вручную (см. ниже).

## Запуск тестов

### Собственный тест

В репозитории имеется автономный файл `src/custom_test.cpp`, который проверяет, что все сообщения обрабатываются без потерь и дубликатов при конкурентной нагрузке.

Скомпилируйте и запустите:

```bash
/opt/homebrew/opt/llvm/bin/clang++ -std=c++20 -O2 -pthread -Isrc src/custom_test.cpp -o custom_test
./custom_test
```

Ожидаемый вывод:

```
Ожидалось сообщений: 16000
Выведено сообщений:  16000
Затраченное время:    ... мс
Тест пройден: все сообщения обработаны.
```

### Оригинальный каркас тестов

Файл `src/tests/test.cpp` можно скомпилировать, передав нужные макросы и добавив свою функцию `main`. Пример:

```bash
/opt/homebrew/opt/llvm/bin/clang++ -std=c++20 -O2 -pthread -Isrc \
    -DLOGGER_HEADER='"logger.hpp"' \
    -DLOGGER_NAME=logger \
    src/tests/test.cpp ваш_main.cpp -o test_logger
```

Вам нужно будет либо найти оригинальный `main`, либо написать собственный, который запускает зарегистрированные тесты.

## Детали реализации

Логгер использует простую очередь, защищённую мьютексом. В методе `post` сообщение копируется в `std::string` и добавляется в конец `std::deque`. Условная переменная уведомляет потребителя. В `run` потребитель ожидает на условной переменной, пока не появится сообщение или не будет запрошена остановка. Затем он извлекает сообщения по одному, освобождает блокировку, вызывает `print` и снова захватывает мьютекс. Такой подход гарантирует короткое время удержания блокировки и не блокирует производителей на время вывода.

Использование `std::condition_variable_any` важно, потому что он поддерживает ожидание с `std::stop_token` напрямую.

## Устранение неполадок

- **`std::format_string` не найден**: ваш компилятор/стандартная библиотека не полностью поддерживает C++20. Используйте LLVM из Homebrew или обновите Xcode.
- **`std::atomic::notify_all` не найден**: если вы попытаетесь собрать lock-free версию, учтите, что в libc++ от Apple эти методы могут отсутствовать. Оставайтесь на решении с мьютексом.
- **`cmake` не найден**: установите CMake через Homebrew (`brew install cmake`) или скачайте с cmake.org.
- **`brew` не найден**: сначала установите Homebrew (`/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`).
